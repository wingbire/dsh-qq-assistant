# 设计取舍

> 这份记录想回答的不是"做了什么"，而是"**为什么这么做**"，以及**踩过哪些坑**。
> 有些取舍看起来反直觉，但都有测量支撑。

## 1. 人设为什么放 `personaPrefix` 而不是消息体

**问题**：人设每次调用都要带，放消息体里相当于每轮重复付费。

**选择**：写进 DSH profile 的 `system-prompt.config.personaPrefix`。

**理由**：DeepSeek 的前缀缓存按**逐字节相同的最长前缀**命中。人设固定在最前段、且三档之间完全一致时，
这一大段就一直在缓存里。实测命中率 **94.0% / 96.1%**，而缓存读的价格约是输入价的 1/10。

**代价**：改人设会让缓存失效一次（重新预热）。所以「保存人设」是显式动作，不做输入即生效。

## 2. 为什么是「一个 profile + 三档补丁」而不是三个 profile

**反直觉的点**：直觉上三档 = 三个 profile。

**但**：三个 profile 各自有一份脚手架（工具说明、运行时上下文），人设前缀在里头**不再逐字节相同** ——
缓存各算各的，换档就丢缓存。改成「一个 profile + 三个 overlay」后，人设那段完全共享，**跨档命中**。

## 3. 为什么工作区自带 DSH_HOME

**约束**：不碰用户的 `~/.dsh`。

**做法**：`DSH_HOME=<项目>/app/dsh-home`，profile / 人设 / 技能 / 会话全在里面。
好处不只是"干净"：**卸载 = 删目录**，迁移 = 拷贝目录，不会跟用户别的 DSH 用法互相污染。

## 4. 为什么坚持零 npm 依赖

**动机**：分发版要能"解压就能跑"。

**所以自己写**：WebSocket 服务端与客户端（RFC6455 文本帧）、SQLite 读写（走 Node 24 自带的 `node:sqlite`）、
语音合成（调 Windows 自带 SAPI）、配置端前端（原生 HTML/CSS/JS + 手写 SVG 图表）。

**代价**：mock OneBot 服务器、mock DSH CLI 也都是自己写的 —— 但这反而让测试完全不依赖外部服务。

## 5. 为什么先本地判定、后调模型

**动机**：群里绝大多数消息不是跟机器人说的。

**做法**：六因子加权 → p_say → 三阈值。低于开口线**一个字都不发**，一分钱不花。
只有**高档**（或被"语义补救"抬起来的那种）才送外审复核一次，只有确定要回才送大脑。

**这是整个项目最值钱的一条**：它决定了账单，而不是决定了效果。

## 6. 灰区为什么要有「本地短答」

外审说"否/不确定"时如果直接放弃，会有一种尴尬：**明明该接一句轻松的，却完全不理人**。
（现在外审可以明确回一个"短"，这层就判得更准了。）

所以加了一层：p_say 够就**本地短答**（模板 + 关键词，不走模型，零成本）。
它牺牲了一点自然度，换来了"被搭话一定有回应"。

**但它后来成了另一个坑**：实测群里的 `sent` 记录全是 `嗯？/咋了/啥事/在的` 在循环 ——
用户当着它的面吐槽「只会嗯嗯啊啊说是」，而那几条抱怨**自己也被这句"嗯？"兜掉了**。
根因是三件事叠一起：池子只有 4 句、随机抽取没有记忆、而且不看场景（图片、语音、情绪全用同一套）。

修法对应三条：**分场景分池**（寒暄 / 被点名 / 情绪 / 图片 / 语音 / 各 bucket）、
**同群最近 6 条不重复**（落盘 `localreplies.json`，重启也记得）、
**图片语音直接说实话**（"图我这边没看到内容，你描述下？"）—— 零成本也能有分寸。

**教训**："不花钱的那一层"同样会被人天天看到。省钱的设计不能只算钱，还要算"一天重复八遍有多难看"。

## 7. 为什么连发要合并

群里常见的是**同一个人连发三四条**（打字慢，一条条补）。逐条判定会：重复回、判定依据被切碎、还容易被当成刷屏。

`coalesceWindowMs` 默认 6 秒，同一个人的连发并成**一轮**判定 + 一次回复。
副作用是延迟高了最多 6 秒 —— 但在群里这个延迟是自然的（人也在等你打完字）。

## 8. 立绘为什么按「当前形态」而不是让模型自己选

模型没看过图，让它选只能瞎编。所以做成**配置项**：`persona.ageStage`（幼年/成年）决定人设里的形体描述，
也决定 `[立绘]` 发哪张。要换形态就改配置，模型不需要"懂"图片。

顺带解决了另一个问题：**每群专属人设只能走消息体**（进系统提示词的话每个群都要一份 profile，一改就打散缓存），
而全局的形体描述可以常驻前缀 —— 这两件事被分开了。

## 9. 社区插件为什么不打包

Our Free Model / dsh-free-search / archify / dsh-meme 都是社区做的 DSH 插件。

**不打包的理由**：体积、许可证、以及它们本来就该由 DSH 那边管。
本程序只做**兼容层**：探测装没装、配置翻译成能用的形式、提供一键安装与降级。

**降级是这个设计的重点**：没装 dsh-free-search 就退回内置直搜；没装 archify 就不画图；
关掉 dsh-meme 人设里连配图规则都不写 —— **模型不会去用它没有的能力**。

## 10. 踩过的坑（有参考价值的那种）

### 命名互斥体被 GC 回收，单实例静默失效

第一版启动器单实例是教科书写法：

```csharp
var mutex = new Mutex(true, "Local\\App.Single", out createdNew);
if (!createdNew) return;
```

**实测无效**：连开三次起了三个实例。原因不在互斥体，在 **GC** —— `mutex` 是局部变量，检查完再没被引用，
`/optimize+` 下 JIT 判定它已死即可回收 → 终结器关闭句柄 → **命名互斥体随之消失** → 下一个实例自然又"创建成功"。
改成**静态字段持有**（+ `GC.KeepAlive`）后正常。

### `spawnSync` 卡住整个事件循环

语音合成最初用 `spawnSync` 调 PowerShell + SAPI。结果每合成一条语音，
**整个进程卡住 1~2 秒**：心跳、其它群的消息、定时 tick 全停。

改成异步 `spawn` + Promise 打包，指令注册表也跟着支持 async handler。
顺带暴露了那个演示脚本的问题：它原来是靠"阻塞"恰好通过的，改成异步后等待不足，两边都修了。

### 一份程序，两份 NapCat

启动器的 NapCat 探测第一版选中了 `E:\NapCat\bootmain\NapCatWinBootMain.exe`，
而**真正在跑的是**另一份 `E:\Napcat\<某个 Shell 目录>\QQ.exe`。后果很实在：探测报"没在跑"、退出时该关的一个都没关掉。

修法两条：**候选打分选本体**（同目录下有 `QQ.exe` 的 +4、目录名带 Shell 的 +2），
**范围抬级**（exe 落在 `bootmain` 这类子目录里就把判定范围抬到上一层，带盘根保护）。

### 探测请求会掩盖真实原因

OneBot 客户端最初在 token 不对时的表现是"连上 → 断开 → 重连"，日志里只有 `closed`。
用户看到的是"状态不变绿"，完全查不出是 token 问题。

后来单独识别服务端的错误回包（`retcode != 0` 且无 `echo`），设成独立状态 **rejected** 并保留服务端原话；
再修一个更隐蔽的：`onerror` 会先于 `onclose` 触发，把 rejected 覆盖成 error —— 两个 handler 都要保护这个状态。

**教训**：错误状态要尽量**接近原因**，别让它退化成一句"失败了"。

### 令牌被「已配置」三个字吃掉了

配置端对 `secret` 字段一贯的做法是：**永不回明文**，只回 `<已配置>`；前端也把它当"没填"用 ——
密码框空着，占位提示写"已配置（留空不改）"。

坑在保存：前端是**把整份 values 原样回存**的，那份 values 里就有 `<已配置>`。
后端直接 `deepMerge`，于是真令牌被三个字覆盖 → 客户端带着假令牌去连 → NapCat 拒掉。
用户看到的现象是"重启之后就再也连不上了"，而配置端那一栏看起来**还写着"已配置"**。

修法：`mergeConfigSafe` 把 secret 的**遮蔽值和空串都当成"没改"**（这正是"留空不改"的字面意思），
真填了新值才写进去。回归测试照着「GET → 原样 POST」那条路走一遍，专门盯这个。

**教训**：遮蔽（redact）只在**出**的方向安全。只要那份数据还可能被**原样送回来**，
入的方向就必须把占位符重新解释成"不改"，否则秘密会被自己的占位符覆盖。

### undici 的 ErrorEvent 里什么都没有

Node 自带的 `WebSocket` 连不上时给的是 `ErrorEvent`：`message` 是空串，
`error` 是个**消息也为空的 TypeError**，没有 `cause`、没有 `code` ——
`String(e)` 只能得到 `[object ErrorEvent]`，排查时等于零信息。

修法两层：① 错误文本优先取 `e.error.message`；② 拿到 `1006`（没收到正常关闭帧）时
**自己戳一下 TCP 端口**，把「端口没开」和「端口通了但握手没过」分开说。
日志于是从一句 `onebot: closed` 变成
`连不上 127.0.0.1:3001 —— connect ECONNREFUSED（NapCat 没起来，或它的 WebSocket 服务端没开）`。

**教训**：运行时给的"错误对象"未必带原因。拿不到原因时，**主动验证一个能验证的事实**（这里的端口），
比把 `[object Xxx]` 原样打印强。

### 开口和深度是两个人决定的，外审却只审了一个

最早的二判只在**高档**触发，而且它问的是"值不值得开口回复" —— 可它拿到消息时，
本地已经决定"要回"了，于是它唯一的用处是**压低深度**（否 → 压成一句短话）。真正的错位在两头：

- **该回的被判否**：没点名的真问题（"这个报错怎么解"）本地 pSay 天生偏低（没人 @ 它、还压着成本项）
  → 直接 ignore，**外审根本没机会看到它** —— 而 rubric 第 4 条明明写着这类该回；
- **该短的被当成长篇**：见上一条坑（U 里的成本项让"要求详细"反而更容易掉进短句）。

修法是把外审从"高档审深度"改成**按不确定度择机复核**，输出从两档扩成三档
（**是 / 短 / 否**）：一次调用同时定"开口"和"深度"，判否就**真的不回**。
触发面由 `audit.scope` 控制（默认 = 高档 + 规则救回来的那种），再用 `audit.maxPerHour` 封顶，
免得灰区全审把延迟和额度堆起来。

**教训**：一个"复核者"如果只被允许否决其中一个维度，它就会变成那个维度的补丁。
先问清楚"我要它复核的是哪几件事"，再决定它在流水线的哪一段被调用。

### 人设里写了做不到的能力

最早的人设装配只看**开关**：`vision.enabled=true` 就写「你看得到图」，`voice.enabled=true` 就写「你能发语音」。
于是把识图模型换成一个纯文本模型之后，人设还在说"你看得到图" —— 模型就对着空气聊图片
（实测日志里全是 `vision_fail: 模型没返回描述`，而人设仍在宣称看得见）。语音那侧同理：
音色名写错、或者换了台没有 SAPI 的机器，人设照样说"我能发语音"。

修法：**人设里的每条能力声明，都先问一遍"这台机器真做得到吗"** ——
看图按模型名判（认不出就当没有）、发音探本机 SAPI 音色、听语音是常量（本程序不做转写，直接写【听不到语音】）。
顺带把"可变段"整段挪到人设末尾：开一个开关只改尾巴，前面的前缀缓存不受影响。

**教训**：能力声明是给模型看的"世界观"。世界观和现实不一致时，模型会自信地演下去，而不是报错。

### 只活在内存里的状态（同一类坑，一次扫干净）

「跳过观察期」按钮点了没用，根因是**分群阶段只存在内存里**，重启就复位。顺着这条线把
"用户/程序攒出来、重启就没了"的状态扫了一遍，同类的还有三处：

| 状态 | 原来的样子 | 后果 |
|---|---|---|
| 分群阶段（观察 / 半自动 / 全自动） | 内存 Map | 点了「跳过观察期」，重启回到观察期；**观察计数**也归零，于是"攒够 80 条转半自动"永远攒不满 |
| 今日已用 token（日预算） | 只在 SIGINT 里存，而且**从没读过** | 托盘是 `taskkill /F` 收尾，SIGINT 根本不执行 —— 日熔断形同虚设，重启就能再花满一份 |
| 按群暂停（群内 `/停` + 配置端"关掉本群"） | 内存 Map | 让它闭嘴，重启后它又开口 —— 刹车失效比不回话更糟 |
| 学到的 arm 权重 | `saveState()` 写了却**没人调用**，只剩 SIGINT 那条死路 | 学习成果每次重启清零 |

现在这四份状态都落盘（`data/stages.json` / `budget.json` / `brakes.json` / `bandit-state.json`）：
显式动作立刻写、高频计数攒 1~2 秒写、退出时再 flush 一次。

**教训**：内存里放状态很舒服，但每加一处都得问两句 ——「**重启后还在不在**」，
以及「**退出那条路真的会走到吗**」。托盘是强杀，任何"退出时才存"都等于没存。
测试也照这个写：**新实例 + 同一个文件**，断言状态还在。


### NapCat 的令牌该由 NapCat 说了算

令牌两边都靠手抄，就一定有写岔的一天；写岔的症状（连不上 / 被顶掉）和"没配"几乎一样，
而两边的界面看上去都"配好了"。

所以配置端会去读 NapCat 自己的 `onebot11_*.json`：**本机没填就自动填**；
**地址相同而令牌不一样，就以 NapCat 为准**（那份才是它认的）；地址都不一样则只提醒、不乱改；
NapCat 里压根没有启用的 WebSocket 服务端时，直接告诉用户去它网页控制台开一个。
读不到配置就老老实实退回手填 —— 自动对齐只在**读得到事实**时才动手。
