# 路线图与已知限制

## 已知限制

### 功能上

| 限制 | 说明 | 现状 |
|---|---|---|
| **OFM 免费池在 headless 下返回空文本** | Our Free Model 的 provider 路由已验证可解析，但实测几个免费模型都返回空串 | 两路开关**默认关闭**；等你确认哪个模型能出字再开 |
| **archify 真实渲染未端到端验证** | 标记解析 → 发送 → 删本地这条链路有测试；但"多步渲染出 PNG"没跑过完整实例 | 装好技能后需在真实会话里验一次 |
| **语音依赖 Windows SAPI** | 只有 Windows 能合成 | 非 Windows 可关掉语音，其余功能不受影响 |
| **识图需要外部多模态** | `http` 后端要你自己提供 OpenAI 兼容接口 | 默认关闭 |
| **只支持 OneBot v11** | NapCat / go-cqhttp 等 | 够用，但要接别的协议得写适配 |
| **配置端无鉴权** | 只听 `127.0.0.1`，但没有登录 | 设计如此（本机工具）；**别**把它暴露到公网 |

### 效果上

| 限制 | 说明 |
|---|---|
| **新群前 80 条不说话** | 这是设计，不是 bug。想立刻看效果改 `stageMode = live` |
| **自学习需要时间** | 阈值自适应、群档案重炼都靠真实反馈积累，前几十轮效果一般 |
| **本地判定会误判** | 保守方向（宁可少说）是刻意选的；嫌它太闷就调低开口阈值 |
| **≥3 个模型档位的差异** | 三档只改 reasoning effort 与字数上限，不改人设 —— 这是为了缓存 |

## 计划中的方向

### 近期

- [ ] **archify 端到端验证** —— 真实画一张流程图并发进群，把这条从"写了"变成"验过"
- [ ] **OFM 免费池模型摸底** —— 逐个试哪个能稳定出字，试出来就把开关的默认值改掉
- [ ] **60 条判定用例集** —— 覆盖六因子边界与灰区，给判定中枢做一次定型标定
- [ ] **接入适配层** —— 把 OneBot v11 抽出一层接口，方便接别的协议

### 中期

- [ ] **配置端加一层简单鉴权** —— 万一有人想跑在局域网里
- [ ] **群档案的可视化编辑** —— 现在是文本框，可以做成标签云 + 拖拽
- [ ] **多账号** —— 一个进程服务多个机器人账号（现在是靠多开进程）
- [ ] **成本预测** —— 按历史用量预测本月账单

### 想要但没想好怎么做

- **语气连续性**：现在每轮独立，接不住"上一轮我用的什么腔调"
- **图片生成**：现在只能画结构图（archify），不能画画
- **跨群记忆**：现在群与群完全隔离（这是刻意的），但"这个人在这两个群里"其实可以是同一个人

## 贡献

欢迎提 issue 和 PR，尤其下面这些：

- **新的本地判定因子** —— 现在六个，语义/连续性/需求的实现都比较粗糙
- **别的地方的 B 通道** —— 现在 B 通道是"让 DSH 搜一次再总结"，可能还有更省的
- **非 Windows 的语音后端** —— 现在只有 SAPI

改之前建议先读 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [DESIGN.md](DESIGN.md)；
跑 `node test/run-tests.mjs` 应当是 **167 项全过**，加了功能记得补测试。
