# 与 AI 结对开发：通用技巧与要避免的坑

> 素材全部来自本项目（dsh-qq-assistant 3.0）的真实开发过程，每个例子都是**实际发生过**的。
> 写给"要指挥 AI 写代码的人"看 —— 不是写给 AI 看的。

---

## 0. 一句话结论

**AI 不擅长猜你要什么，但非常擅长执行"可验证的具体动作"。**
所以高效的用法是：把模糊诉求翻译成**现象 + 约束 + 验收命令**，让它每一步都能自证；
同时**别让它在同一轮里既改行为又顺手重构**——本项目的三次翻车全是"顺手"造成的。

---

## 1. 怎么描述需求最省轮次

| ❌ 这样说 | ✅ 这样说 | 为什么（本项目实例） |
|---|---|---|
| 「它呆呆的、没过脑子」 | 「@ 到了、也判成该回，却回『嗯？』；一句『展开说说』回『啥事』」 | 前者我花了几轮去猜；后者一句话就能在代码里定位到"深度分档把中档压成低档" |
| 「小助手还是没法自动登录」 | 「重启后日志有 \`onebot: connecting\`，配置端能看到群消息，但它不回复」+ 日志片段 | 有现象+证据，直接查到 \`brain_error: Authentication Fails\`（key 被误填进死字段） |
| 「优化一下判定」 | 「进大脑要有语义理由；灌水/情绪话别调模型」+ 给出 3 条真实消息做反例 | 有反例才能写成断言，也才能回归 |
| 「文档和代码不一致，改改」 | 「先对一遍：文档说灰区送二判，代码里灰区根本不触发」 | 指出具体矛盾点，比"全面检查"快得多 |
| 「顺便把另一个仓库删掉」 | 「删 \`origin\` 远端，保留 \`public\`」（单独一条） | "顺便"类跨领域操作最容易做错且不可逆 |

**三条通用配方：**
1. **现象 + 期望**：现在是什么样、你希望是什么样（最好各给一条真实消息/截图/日志）。
2. **约束**：「只改 \`app/src/gates.js\`」「不要动默认值」「这个文档不要进仓库」。
3. **验收**：「改完跑 \`node test/run-tests.mjs\`，输出应为通过 N 项」「群里的图要能被回复到」。

## 2. 让 AI 干活的标准动作（本项目验证有效）

1. **先盘点、再动手**：让它先"找出同类问题"（本项目一次扫出：遮蔽值被写回、内存态丢失、配置项是死旋钮、三档 effort 没接线、灰度没送外审）。盘点成本很低，比一个个碰强。
2. **探针优先于猜测**：不靠推理，先写一次性脚本跑真实链路。
   - 例：\`audit-probe\`（外审通道到底通不通）、\`vision-live-probe\`（拿真图跑一次识图）、
     \`expr-live-test\`（真机验"文字+立绘+图表+表情包"能否发出）、\`cost-report\`（真实用量折算成钱）。
   - 探针跑出的事实**直接推翻**了"应该没问题"的假设（外审一直在返回"不确定"）。
3. **小步改 + 立刻验证**：一次只改一个机制，马上跑测试/渲染对比（本项目每轮都跑 200+ 项回归）。
4. **把"口味"和"事实"分开**：灰区下限 0.4 是口味（你不用懂），key 失效是事实（必须查）。
5. **要求四件套同步**：代码 + 测试 + 文档 + 文档里的计数（\`tests-208 passing\` 这种改一个漏一处会自相矛盾）。
6. **让它把结论落成"可复算"的东西**：成本文档不是手写数字，而是 \`demo/cost-report.mjs --doc\` 生成；改价目表重跑即可。

## 3. 怎么确认它"真的做到了"

只接受**能复现的证据**，不接受"我改好了"：

| 证据类型 | 本项目里的样子 |
|---|---|
| 命令原始输出 | \`通过 208 项，失败 0 项\`、\`9/9\`、\`13/13\` |
| 一行日志 | \`onebot: open\`、\`能力声明 · 看图：会写进人设（跟随大脑模型）\`、\`brain_error: Authentication Fails\` |
| 远端 = 本地 | 推完必须核对 \`远端 = 本地 = <sha>\`（本项目 GitHub 经常 reset，出现过"以为推上去了"） |
| 真实产物 | 群里真的收到了一张图 / 状态页真的显示 \`¥0.0037\`（截图） |
| 自动生成的对照表 | 24 条情景"本地 ↔ 外审"对照（一致率 15 → 20/24，多嘴 8 → 0，漏接 1 → 0） |

> 反例：本项目曾出现"文档写灰区送二判、代码根本不送"——**文档通过不等于代码通过**，一定要看日志或产物。

## 4. 容易翻车的 12 个场景（都踩过）

1. **批量替换数字**：用 sed 把测试数 200→203 时，顺手把 \`20000\` 改成 \`20300\`、\`[20,60,200]\` 改成 \`[20,60,203]\`。
   → 规则：**数字替换要带词边界/上下文**，改完 grep 一遍可疑值。
2. **字符串里的引号**：中文提示词里混入 ASCII 双引号，导致 \`node\` 语法错误、**程序启动直接崩**（踩了三次：main.js / dshprofile.js / demo 脚本）。
   → 规则：让它加**语法防呆测试**；并要求"提交前自检"。（本项目后来发现 \`node --check\` 对 .js 是假通过，改成拷成 .mjs 再查。）
3. **配置项是死旋钮**：\`runtime.vision.model\` 配了没人读、\`groupHourlyLimit\` 定义了没人调、三档 \`reasoningEffort\` 没接线。
   → 规则：新增/修改配置项时，**要求验证"改它真的会改变行为"**（测试或日志）。
4. **只活在内存里的状态**：阶段/预算/刹车重启即失效。
   → 规则：问一句"重启后会怎样"。
5. **遮蔽值被写回**：前端显示 \`<已配置>\`，保存时把真实 token 覆盖成这串字（NapCat 掉线的真凶之一）。
   → 规则：**secret 只在"出"的方向遮蔽**，写回时必须"空/遮蔽 = 不改"。
6. **失败被静默吞掉**：外审认证失败时返回"不确定"，导致"补救回来的消息"被直接丢弃 —— 一整条路径静默失效。
   → 规则：明确"通道不可用时该 fail-open 还是 fail-closed"，并要求打日志。
7. **默认值即成本**：把 \`terseAt\` 从 0.35 调到 0.20，看热闹的闲聊全进模型 → 账单变化。
   → 规则：改默认值时**同时给出成本/延迟影响**（本项目后来专门写了 docs/COST.md）。
8. **密钥进对话**：key 被粘进配置对话、或被误填进 \`brain.dshCliPath\`；真群号/uid 还一度进了公开仓库。
   → 规则：凭据只走配置文件/环境变量；**提交前扫敏感串**（本项目固定做 \`grep -cE 'sk-[A-Za-z0-9]{16,}|<群号>|<uid>'\`）。
9. **忘了重启/重载**：人设、识图、状态页资源都要重启才生效。
   → 规则：改完问"需要重启吗"，并让它顺手重启+贴启动日志。
10. **"顺便"塞需求**：同一轮里塞 4~5 个不相关诉求，容易只做前两个。
    → 规则：一件一件来，或明确"先做 1、2，做完停下汇报"。
11. **一次大改**：整段重写文档/大文件时，转义、缩进、重复段落最容易出问题（本项目一份宣传文档重写后遗留 \`\` 转义残留）。
    → 规则：大改后要求"自检输出前 N 行 + 关键字计数"。
12. **把"应该"当成"实际"**：免费模型池实测不享前缀缓存（\`cacheReadTokens: 0\`）、宣传里却说命中 94%+。
    → 规则：所有对外数字**必须来自实测命令**，并注明样本量。

## 5. 与本项目强相关的约定（可以直接复用）

- **默认值 = 账单**：任何影响"是否调模型"的开关，改默认值都要在文档里写清代价。
- **能力声明要跟着实际能力走**：人设里写"你看得到图 / 你能发语音"之前，先问"这台机器真做得到吗"（本项目为此加了能力判定与诚实话术）。
- **重启才生效**：人设 / 识图 / 语音 / 前端资源。
- **提交三件套**：代码 + 测试 + 文档（含计数），一次 commit 讲清"为什么"。
- **推送必须核对**：\`远端 = 本地\`，网络不稳时重试。

---

## 6. 速查卡（10 条）

1. 给现象，别给评价；给期望，别给"优化一下"。
2. 一条消息一个诉求；跨领域操作单独发。
3. 要验收命令，不要"改好了"。
4. 让它先盘点同类问题，再动手改。
5. 探针/真实链路优先于推理。
6. 一次只改一个机制，改完立刻跑回归。
7. 明确禁改范围：哪些文件、哪些默认值、哪些不上传。
8. 改默认值 → 要成本与延迟影响。
9. 凭据不进对话；提交前扫敏感串。
10. 推完核对「远端 = 本地」。
