# 安装与部署

## 一、前置

| 需要 | 版本 | 说明 |
|---|---|---|
| **Node.js** | ≥ 22（推荐 24） | 程序本体。零 npm 依赖，**不用 npm install** |
| **DSH** | 任意近期版本 | 大脑。装好后把 `dsh.cmd` 路径填进配置端，或让它自动找 |
| **NapCat** | 推荐 NapCat.Shell | QQ 侧。Shell 版自带一份 QQ，大小号天然隔离 |
| **DeepSeek API Key** | — | BYO key，用你自己的账号 |

```bash
git clone https://github.com/wingbire/dsh-qq-assistant.git
cd dsh-qq-assistant
node test/run-tests.mjs       # 先确认环境没问题：应输出 通过 203 项，失败 0 项
```

## 二、装 NapCat（推荐 NapCat.Shell）

**为什么推荐 Shell 版**：它自带一份 QQ、装在独立目录 —— 你的**大号继续用官方 QQ**，
小号跑在 NapCat.Shell 里，两边数据互不打扰；QQ 自动升级也不会把注入打掉。
**不要**给主号在用的 QQ 装注入：QQ 一升级就失效，而且两个号会共用同一份 QQ 数据目录。

```
1. 去 NapNeko/NapCatQQ 的 Releases 下 NapCat.Shell.zip
2. 解压到独立目录（例如 E:\NapCat\）—— 不要放进本项目目录
3. 双击 launcher.bat，用【小号】扫码登录
4. 登录后在它的 WebUI（默认 http://127.0.0.1:6099）里开 OneBot 11 的 WebSocket 服务端
```

> **端口别搞混**：OneBot 端口通常是 **3001**；**6099 是 NapCat 的网页控制台**，不是这个。

## 三、配置

```bash
node app/main.js          # 起程序
# 浏览器进 http://127.0.0.1:8799
```

配置端 9 页，按顺序做：

| 页 | 做什么 |
|---|---|
| **设置** | 先点「检查更新」和「依赖体检」，缺什么一目了然，能一键装的直接装 |
| **接入** | 地址（`ws://127.0.0.1:3001`）和令牌。**令牌不用手抄**：页面上的「NapCat 自动对接」会读 NapCat 自己的 `onebot11_*.json`，没填就自动填、两边不一样就以 NapCat 为准（启动时也会对齐）。**填错会明确告诉你**：端口不通/握手没过/被服务端拒绝，都分开显示 |
| **人设** | 改名字、性格、语气；也能整段手写全局人设。**改动即时生效**（下一轮大脑调用就用新的） |
| **调整** | 开口阈值、三档线、灰区、六因子权重、外审复核范围 / 上限 / 超时策略、预算、搜索。这些阈值**真的会进判定**（点保存即时生效）；点名 / 要求展开 / 问句另有"至少中档"的地板 |
| **额外功能** | 语音 / 识图（内置）；社区插件兼容（四个插件的开关与一键安装）。**能力声明按实际能力写进人设**：识图**默认与大脑同一个模型**（字段里填具体 id 才会另起一个），语音会探本机 SAPI 音色；本程序**不做语音转写**，收到语音会诚实说听不了 |
| **群档案** | 管理员可手改提炼出来的群档案 |
| **状态** | 成本、消息流与判定过程、群切换、快捷控制、预算滑块 |

保存后大部分改动**即时生效**；只有少数接入类参数需要重连（接入页有「重连 OneBot」按钮，不用重启程序）。

## 四、托盘启动器（Windows，可选但推荐）

```bash
launcher\DSHQQTray.exe        # 或双击桌面/开始菜单的「DSH-QQ 群小助手」
```

它会：

- **只允许一个实例** —— 重复双击只是冒个气泡提醒
- **顺带拉起 NapCat**，并**等 OneBot 端口通了**再启动小助手（省得它一上来就疯狂重连）
- **退出时顺带关掉 NapCat** —— 只关**NapCat 目录里的进程**，你自己的 QQ 纹丝不动
- **把 NapCat 藏在后台**：不给它开控制台，并**每 3 秒巡检查一次**把露出来的窗口收起来。
  即使 NapCat 是你自己先启动的（比如双击了它自带的 bat），启动器也会接手把它藏好；
  托盘菜单里有「立刻隐藏 NapCat 窗口」，菜单项文字还会显示还剩几个窗口露着
- **NapCat 掉登录时的两条救命菜单**：
  「显示 NapCat 窗口（登录 / 扫码，10 分钟不自动隐藏）」把被藏起来的登录窗/控制台露出来；
  「复制 NapCat 登录令牌」直接把进网页控制台要填的那串令牌放进剪贴板（它存在 NapCat 的 `webui.json` 里）
- 菜单栏常驻一行**端口状态**：`OneBot 3001 ●通/○不通　控制台 6099 ●通/○不通` ——
  「控制台通、3001 不通」就是 NapCat 活着但服务端没起来（多半 QQ 掉登录）
- 托盘菜单：启动/停止/重启、只启动或只关闭 NapCat、显示/隐藏 NapCat 窗口、复制登录令牌、打开配置端、打开 NapCat 控制台、开机自启

从源码编译：`powershell -File launcher/build.ps1`（用系统自带 csc，不需要装 SDK）。
图标：`launcher/make-icon.ps1` 从一张图生成多尺寸 .ico。

启动器有 `--probe` 模式：只探测不动手，把认定结果写进 `app/dsh-data/_napcat-probe.txt`，排查用。

## 五、分发

```bash
node dist/build-package.mjs
```

**白名单打包** + **双闸门自检**（PATH 闸门 + 内容闸门，扫 `sk-[A-Za-z0-9]{16,}`）。
产物不含：密钥、运行期数据、表情包素材、开发者的任何私有内容。

## 六、排查

| 症状 | 先看 |
|---|---|
| 状态一直「未连接」 | 接入页的「正在连的地址」vs「配置里保存的地址」；端口是不是写成了 6099。日志里会写清是**端口没开**还是**握手没过** |
| 显示「被服务端拒绝」 | 令牌不对。配置端会显示 NapCat 的原话（如 `token验证失败`）；点「从 NapCat 自动填入」即可对齐 |
| 自动对接显示「没找到 NapCat 配置」 | NapCat 装在非常规位置：把「NapCat 启动程序路径」或「NapCat 配置文件路径」填上，再点「重新扫描」 |
| 自动对接显示「NapCat 里没有启用的 WebSocket 服务端」 | 去 NapCat 网页控制台 → 网络配置 → OneBot 11 新建一个 WebSocket 服务端（端口 3001） |
| NapCat 在跑（6099 通）但 3001 一直不通 | **QQ 掉登录了**：托盘 →「显示 NapCat 窗口」扫码；进控制台要的令牌用托盘 →「复制 NapCat 登录令牌」 |
| 它不说话 | **默认观察模式**：攒够 80 条才转半自动。想立刻开口：调整 → 开口阶段 → `stageMode` 改 `live` |
| 一条都回不了 | 设置页 → 依赖体检：DSH 找得到吗？Key 配了吗？ |
| 语音发不出去 | 装 ffmpeg；或者先用 `/说 测试` 让管理员试一次 |
| 想全部停掉 | 安装目录放一个 `STOP` 文件（三路刹车之一） |
