# 回归清单（改判定相关代码前必看）

> 背景：这个项目吃过「修一个冒一个」的亏 —— 判定链路里多处互相影响，
> 靠「在群里试一下」验证不够。下面是硬流程。

## 改动前：跑这两条

```bash
node tools/replay-corpus.mjs     # 用你标注过的真实语料回归（离线、不花钱、结果确定）
node test/run-tests.mjs          # 骨架回归测试
```

- **语料分数不允许下降**（当前基线 49/60）。下降了就是回归，不要发版。
- 语料里「该回却判了 ignore」的那几条，有一部分是回放器的已知偏差：
  历史判定记录里没存 @/引用 标记，回放时丢了硬触发。**新产生的语料会带标记**，偏差会自然收敛。

## 判定链路的唯一判定点（别再分散）

```
本地闸门（gates.js，一条消息判一次）
   └─ 逐条判定结果 decisions[]
        └─ 合并规则（runtime.js）：这批里只要有 brain 就按最近那条，全否才否
             └─ 外审（audit.js）：只给结论，不再拥有第二次否决权
                  └─ 大脑（brain.js）：看完整上下文，输出空 = 这次不说
```

- **不要再加「整批重判」或「二次覆盖」** —— 那会让同一条消息出现多个结论互相打架。
- **不要再用本地短句兜底对话** —— 那会把「沉默」换成「嗯嗯啊啊」。
- 大脑**只调一次**。输出空就是这次不说，不催第二次。

## 新问题怎么处理

1. 先在群里复现，把那条消息**加进语料**（配置端 → 标注 → 重新拉取）；
2. 在配置端标注「该回 / 该短回 / 该不回」；
3. 改代码 → 跑回放 + 测试 → 分数不降才发版；
4. **不要再临时加开关**。真正需要的开关先进字段表评审。

## 闸门设计规范（别再一刀切）

判定/过滤代码只允许三种**硬闸**（是/否），其余一律用打分或提示表达：

| 允许硬闸 | 理由 |
|---|---|
| 安全（疑似注入） | 不照做 |
| 预算（token/钱） | 花完就停 |
| ~~频率（爆发闸）~~ | **已删除**：数量限流会在她正说话时把她掐断，用户明确要求删掉 |

除此之外的规则，**必须是软的**：写进依据、影响档位/口吻、交给大脑，不做二元判决。

硬闸必须带**放行例外**，至少覆盖：

- 点她名字 / @ 她 / 回复她（`hard.strength > 0`）
- 面向全群的问题（你们 / 大家 / 谁 / 有人）
- 她最近 5 分钟内说过话（她还在局里）

并且**每次拦截都要记日志**（reason 或观测），否则没法判断是「守住了」还是「误杀了」。

已按此规范修正的：

- 灌水/单符号：被点名时不拦
- 疑似注入：被点名时不硬拦（回一句玩笑可以，但绝不照做）
- 两人对话：只在「恰好两人 + 交替一来一往 + 她 5 分钟没说话」时拦
- 字数：软区间，超长按标点拆条，绝不丢内容
- 次数：**不做数量限流**（5 分钟 2 条那种已经删掉）。重复说话这件事用**内容判断**：
  新回复和她最近 3 条回复的字面重合度 ≥80% 才不发（duplicate_skip），而不是「这个小时说了几条」
